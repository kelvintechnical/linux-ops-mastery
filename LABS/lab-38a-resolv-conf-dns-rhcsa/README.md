## 🎯 Objective

Configure which DNS servers the system uses — correctly. You'll read `/etc/resolv.conf`'s format (`nameserver`, `search`, `options`), learn why on a NetworkManager system you set DNS through `nmcli` (which *writes* resolv.conf) instead of hand-editing it, configure a search domain, and test resolution. The key lesson: on modern RHEL, `/etc/resolv.conf` is generated — change it at the source.

> **Safety note:** All DNS changes are made on the throwaway **dummy** profile `lab-dns` (on `dummy0`), never your real connection. Teardown removes it; your real resolver is untouched.

---

## 🧠 Concept

`/etc/resolv.conf` tells the resolver which DNS servers to query and how to expand short names. Its directives: `nameserver IP` (up to a few, tried in order), `search dom1 dom2` (domains appended to bare names so `web` tries `web.dom1`), `domain` (single-domain form), and `options` (e.g. `timeout:`, `rotate`, `ndots:`). The catch on RHEL/Fedora: **NetworkManager owns `/etc/resolv.conf`** and regenerates it from connection profiles, so manual edits get overwritten on the next network event. The correct, persistent method is to set DNS on the connection: `nmcli con mod NAME ipv4.dns "1.1.1.1 9.9.9.9"` and `ipv4.dns-search "lab.local"`, then `nmcli con up NAME`. NetworkManager then writes those into `/etc/resolv.conf`. You *read* `/etc/resolv.conf` to verify, but you *write* via `nmcli`.

```
/etc/resolv.conf:
  nameserver 10.88.88.53     → DNS server (in order)
  search lab.local           → append to bare names
  options timeout:2          → resolver tuning
nmcli con mod lab-dns ipv4.dns "10.88.88.53" ipv4.dns-search "lab.local"
nmcli con up lab-dns         → NM regenerates resolv.conf
```

> **Why this matters:** A huge real-world gotcha is editing `/etc/resolv.conf` by hand and watching it revert. RHCSA expects you to configure DNS the persistent way (via the connection), and to know resolv.conf is the *output*, not the source.

## TASK 1 of 2 — Read and set DNS servers

**In plain English:** We read resolv.conf, then set DNS via the connection profile.

---

### Step 1 of 2 — Read the resolver config

**In plain English:** We view `/etc/resolv.conf` and identify its directives.

```bash
cat /etc/resolv.conf
echo "exit was: $?"
```

**Expected output:**

```
# Generated by NetworkManager
search example.com
nameserver 192.168.x.1
exit was: 0
```

**Line-by-line breakdown:**

- `# Generated by NetworkManager` → The header that tells you this file is auto-written — don't hand-edit.
- `nameserver` / `search` → The DNS servers queried and the domains appended to bare names.

**New words in this step:**

- **`nameserver` / `search`** — the resolver's DNS servers and name-completion domains.

---

### Step 2 of 2 — Set DNS the persistent way (`nmcli`)

**In plain English:** We assign DNS servers to the dummy profile and apply it.

```bash
sudo nmcli con mod lab-dns ipv4.dns "10.88.88.53 10.88.88.54"
sudo nmcli con up lab-dns >/dev/null
nmcli -g ipv4.dns con show lab-dns
echo "exit was: $?"
```

**Expected output:**

```
10.88.88.53,10.88.88.54
exit was: 0
```

**Line-by-line breakdown:**

- `nmcli con mod lab-dns ipv4.dns "10.88.88.53 10.88.88.54"` → Set two DNS servers on the profile (space-separated, tried in order).
- `nmcli con up lab-dns` → Apply; NetworkManager regenerates `/etc/resolv.conf` with these servers.
- `nmcli -g ipv4.dns con show lab-dns` → Confirm the stored value.

**New words in this step:**

- **persistent DNS** — set on the connection so it survives reboots and NM events.

## TASK 2 of 2 — Search domains and testing

**In plain English:** We add a search domain, then test resolution.

---

### Step 1 of 2 — Configure a search domain

**In plain English:** We set a DNS search domain on the profile so bare names expand.

```bash
sudo nmcli con mod lab-dns ipv4.dns-search "lab.local"
sudo nmcli con up lab-dns >/dev/null
nmcli -g ipv4.dns-search con show lab-dns
```

**Expected output:**

```
lab.local
```

**Line-by-line breakdown:**

- `nmcli con mod lab-dns ipv4.dns-search "lab.local"` → Adds `search lab.local`, so `getent hosts web` will also try `web.lab.local`.
- `nmcli -g ipv4.dns-search con show lab-dns` → Confirm the stored search domain.

**New words in this step:**

- **search domain** — appended to bare names during resolution.

---

### Step 2 of 2 — Test resolution

**In plain English:** We verify the resolver answers using the configured path.

```bash
getent hosts localhost
echo "--- resolver state ---"
resolvectl status 2>/dev/null | grep -i 'dns servers' | head -n 2 || cat /etc/resolv.conf
echo "exit was: $?"
```

**Expected output:**

```
127.0.0.1       localhost
--- resolver state ---
   DNS Servers: 10.88.88.53 10.88.88.54
exit was: 0
```

**Line-by-line breakdown:**

- `getent hosts localhost` → A baseline resolution that always works, confirming the resolver path is intact.
- `resolvectl status | grep 'DNS Servers'` → Shows the active DNS servers (fallback to `cat /etc/resolv.conf` if `resolvectl` is absent).

> **Note:** `10.88.88.53` is a lab placeholder — real lookups against it will time out, which is expected. The point is *configuration*, not reaching that server.

**New words in this step:**

- **resolver state** — the active DNS servers the system is using right now.

## ⚠️ Common Pitfalls

| Mistake | Symptom | Fix |
|---|---|---|
| Hand-editing resolv.conf | Reverts on NM event | Use `nmcli ipv4.dns` |
| Forgetting `con up` | File not regenerated | Activate the profile |
| Confusing dns vs dns-search | Names don't expand | Set `ipv4.dns-search` |

---

## 📌 Exam Strategy

On RHEL, `/etc/resolv.conf` is generated by NetworkManager — set DNS via `nmcli con mod ipv4.dns`/`ipv4.dns-search`, then `con up`. Read resolv.conf only to verify. Hand-edits revert; that's the trap.

- `nameserver`/`search`/`options` are the directives.
- Configure DNS on the connection, not the file.
- Verify with `resolvectl status` or by reading resolv.conf.
