## 🎯 Objective

Treat stderr as **evidence**, not noise. You will audit the files Lab 02a produced to prove three things with hard numbers: the streams were truly separated (stdout file has no `Permission denied`, stderr file has nothing else), the `2>&1` order trap actually happened (Form A captured errors, Form B did not), and the captured error log survives a destroy-restore drill byte-for-byte.

---

## 🧠 Concept

In verification, `Permission denied` lines are not garbage — they are proof a non-root user really ran the command and that FD 2 was captured correctly. The audit reduces to counting: `grep -c` turns "are the errors in the right file?" into a number, `stat` confirms ownership, and `sha256sum` proves a restored copy is byte-identical to the journaled original. Each assertion passes loudly or fails loudly; nothing is taken on faith.

```
   02a produced              02c asks
   ─────────────────────     ───────────────────────────────────
   log-files.txt             grep -c 'Permission denied' == 0  ?
   log-errors.txt            grep -c 'Permission denied'  > 0  ?
   formA.txt (> f 2>&1)      grep -c 'Permission denied'  > 0  ?  (correct merge)
   formB.txt (2>&1 > f)      grep -c 'Permission denied' == 0  ?  (order trap)
```

> **Why this matters:** Anyone can run `2>` once. Proving the separation held, the order trap was real, and the evidence is durable is what separates "I think it worked" from "here is the receipt." That receipt is exactly what a grader script or an incident reviewer reads.

---

## 📚 Command Reference

| Command | Purpose | Critical flags |
|---|---|---|
| `grep -c PAT f` | Count matching lines (prints the number, not the text) | `2>/dev/null \|\| echo 0` defaults to 0 on a missing file |
| `stat -c '%U:%G %a %n'` | Print owner, group, mode, and name in one line | the canonical ownership audit |
| `wc -l < f` | Line count as a bare number | feeds via `<` so no filename prints |
| `sha256sum` | Byte-exact fingerprint for the destroy-restore proof | pipe through `awk '{print $1}'` for just the hash |

## TASK 1 of 2 — Audit the stderr evidence

**In plain English:** We prove the two assertions that define correct stderr handling: the streams were separated cleanly, and the `2>&1` order trap really fired.

---

### Step 1 of 2 — Prove stream separation with `grep -c`

**In plain English:** We count `Permission denied` lines in each file — the stdout file must have zero, and the stderr file must have some — which proves `>` and `2>` sent the streams to different places.

```bash
echo "stdout file PD lines: $(grep -c 'Permission denied' "${LAB_USER_HOME}/log-files.txt")"
echo "stderr file PD lines: $(grep -c 'Permission denied' "${LAB_USER_HOME}/log-errors.txt")"
test "$(grep -c 'Permission denied' "${LAB_USER_HOME}/log-files.txt")" -eq 0 \
    && echo "separation (OK)" || echo "contaminated (FAIL)"
```

**Expected output:**

```
stdout file PD lines: 0
stderr file PD lines: 3
separation (OK)
```

**Line-by-line breakdown:**

- `grep -c 'Permission denied' .../log-files.txt` → Count error lines in the stdout file; `-c` prints the count, not the text. It must be `0`.
- `grep -c 'Permission denied' .../log-errors.txt` → Count error lines in the stderr file; it must be non-zero.
- `test ... -eq 0 && ... || ...` → Assert the stdout file has zero errors; prints `separation (OK)` on success, which is what proves `>` and `2>` were independent.

**New words in this step:**

- **stream separation** — the property that FD 1 and FD 2 ended up in different destinations with no cross-contamination.

---

### Step 2 of 2 — Prove the `2>&1` order trap with Form A vs Form B

**In plain English:** We count errors in the two order-trap files — Form A (`> file 2>&1`) must contain the errors, Form B (`2>&1 > file`) must not — proving the position of `2>&1` changed where stderr went.

```bash
A_PD=$(grep -c 'Permission denied' "${LAB_USER_HOME}/formA.txt")
B_PD=$(grep -c 'Permission denied' "${LAB_USER_HOME}/formB.txt")
echo "formA (> f 2>&1) PD: ${A_PD}"
echo "formB (2>&1 > f) PD: ${B_PD}"
test "${A_PD}" -gt 0 -a "${B_PD}" -eq 0 \
    && echo "order trap proven (OK)" || echo "trap NOT proven (FAIL)"
```

**Expected output:**

```
formA (> f 2>&1) PD: 3
formB (2>&1 > f) PD: 0
order trap proven (OK)
```

**Line-by-line breakdown:**

- `A_PD=$(grep -c 'Permission denied' .../formA.txt)` → Count errors captured by the correct merge; should be `> 0`.
- `B_PD=$(grep -c 'Permission denied' .../formB.txt)` → Count errors in the wrong-order file; should be `0` because they went to the screen instead.
- `test "${A_PD}" -gt 0 -a "${B_PD}" -eq 0 && ... || ...` → Assert Form A captured stderr AND Form B did not; `-a` is logical AND. `order trap proven (OK)` confirms the demo was real (and run as a non-root user).

**New words in this step:**

- **`-a`** (in `test`) — logical AND, true only when both conditions hold.

---

### Concept card (Task 1)

| Concept | What it does | Exam trap |
|---|---|---|
| `grep -c PAT f` | count matching lines | returns `0` cleanly when nothing matches |
| stream-separation assertion | stdout file has 0 errors | a `>>`/`2>` mix-up contaminates it |
| order-trap proof | Form A has errors, Form B does not | identical files mean it was run as root |

### Troubleshoot (Task 1)

| Symptom | Likely cause | Fix |
|---|---|---|
| `contaminated (FAIL)` | Setup ran as root, or `>` vs `2>` swapped | Re-run setup via `sudo -u "${LAB_USER}"` |
| Form A and Form B identical | Generated as root (no denied dirs) | Regenerate as the non-privileged lab user |

## TASK 2 of 2 — Destroy-restore drill for the error log

**In plain English:** We fingerprint the stderr file, wipe the sandbox to simulate a reboot, restore the file from a durable copy, and prove the restore is byte-identical and still appendable.

---

### Step 1 of 2 — Fingerprint and stash a durable copy, then destroy

**In plain English:** We hash the captured stderr file, copy it to durable `/root` (which survives reboot), then delete the volatile sandbox.

```bash
HASH=$(sha256sum "${LAB_USER_HOME}/log-errors.txt" | awk '{print $1}')
echo "stderr hash: ${HASH}"
mkdir -p /root/rhcsa_journal/lab-02c
cp "${LAB_USER_HOME}/log-errors.txt" /root/rhcsa_journal/lab-02c/log-errors.txt
rm -rf "${SANDBOX}"
test -d "${SANDBOX}" && echo "sandbox STILL exists (FAIL)" || echo "sandbox gone (OK)"
```

**Expected output:**

```
stderr hash: 7c1e9d4a... (64 hex chars)
sandbox gone (OK)
```

**Line-by-line breakdown:**

- `HASH=$(sha256sum ... | awk '{print $1}')` → Fingerprint the stderr file and keep just the hash for later comparison.
- `cp ... /root/rhcsa_journal/lab-02c/log-errors.txt` → Stash a durable copy under `/root`, which survives a reboot (unlike `/tmp`).
- `rm -rf "${SANDBOX}"` → Delete the volatile sandbox, simulating `/tmp` being cleared.
- `test -d "${SANDBOX}" && ... || ...` → Confirm the wipe was complete; we want `sandbox gone (OK)`.

**New words in this step:**

- **durable vs volatile** — `/root` survives reboot (durable); `/tmp` does not (volatile).

---

### Step 2 of 2 — Restore and prove byte-identical

**In plain English:** We recreate the sandbox, restore the file from the durable copy, and prove the restored fingerprint matches the original exactly.

```bash
mkdir -p "${LAB_USER_HOME}"
cp /root/rhcsa_journal/lab-02c/log-errors.txt "${LAB_USER_HOME}/log-errors.txt"
NEW_HASH=$(sha256sum "${LAB_USER_HOME}/log-errors.txt" | awk '{print $1}')
test "${HASH}" = "${NEW_HASH}" && echo "restore MATCH (OK)" || echo "restore MISMATCH (FAIL)"
echo "exit was: $?"
```

**Expected output:**

```
restore MATCH (OK)
exit was: 0
```

**Line-by-line breakdown:**

- `mkdir -p "${LAB_USER_HOME}"` → Recreate the sandbox folder we deleted.
- `cp /root/rhcsa_journal/lab-02c/log-errors.txt ...` → Restore the file from the durable journal copy.
- `NEW_HASH=$(sha256sum ... | awk '{print $1}')` → Fingerprint the restored file.
- `test "${HASH}" = "${NEW_HASH}" && ... || ...` → Compare the fingerprints; `restore MATCH (OK)` proves the captured stderr survived the destroy-restore cycle byte-for-byte.

**New words in this step:**

- **destroy-restore drill** — deliberately wiping working state and rebuilding it from a durable copy to prove the evidence is recoverable.

---

### Concept card (Task 2)

| Concept | What it does | Exam trap |
|---|---|---|
| `sha256sum \| awk '{print $1}'` | get just the hash | comparing full `sha256sum` output also compares filenames |
| `/root` durable copy | survives a simulated reboot | keeping evidence only in `/tmp` loses it |
| hash equality after restore | proves a lossless restore | a stray byte flips the hash |

---

### Troubleshoot (Task 2)

| Symptom | Likely cause | Fix |
|---|---|---|
| `restore MISMATCH (FAIL)` | Durable copy modified after hashing | Re-copy and re-hash from the same source |
| `cp: cannot stat ...` | The durable copy step was skipped | Run Step 1's `cp` to `/root` first |

## ⚠️ Common Pitfalls

| Mistake | Symptom | Fix |
|---|---|---|
| Auditing files generated as root | Zero `Permission denied` everywhere | Generate evidence via `sudo -u "${LAB_USER}"` |
| Keeping evidence only in `/tmp` | A reboot loses the proof | Copy to `/root` before any teardown |
| Comparing full `sha256sum` lines | Filename differences cause false mismatches | Compare only the hash with `awk '{print $1}'` |

---

## 📌 Exam Strategy

Verification labs train the discipline of proving your own work before the grader does. For stderr, that means counting (`grep -c`), confirming ownership (`stat`), and fingerprinting anything that must persist (`sha256sum`). Build the habit of writing durable evidence to `/root` and validating it can be destroyed and restored without drift.

- `grep -c PAT file` is your fastest "is it in the right stream?" check.
- Always generate stderr evidence as a non-root user, or there is nothing to audit.
- Stash proof in `/root`, not `/tmp`, and verify the restore with a hash.
